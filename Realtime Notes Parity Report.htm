01

The read

This is a strong document engine wearing a thin application. The gap to AFFiNE, Docmost, and Outline is almost never in the editing loop — it is in the twenty small products those three built around it.

What is already ahead. Per-page hibernating Durable Objects with merged SQLite update chunks, 30-second R2 compaction, IndexedDB offline persistence, and epoch-safe version restore give a better idle-cost and offline story than Docmost or Outline, which both need a permanent Postgres, a Redis, and a separate Hocuspocus process to do less. The operational discipline — worker integration tests, a Chromium E2E suite, coverage gates, a realtime load script, nine operator docs — is ahead of what a project this young usually carries. Attachment handling (range requests, conditional ETags, nosniff, MIME rejection, multipart direct-to-R2) is more careful than Outline's.

Where the distance is. Outline exposes thirty-nine API resource areas and runs about seventy background task types. Docmost ships forty-eight migrations covering spaces, groups, labels, watchers, notifications, page permissions, audit, SCIM, MFA, LDAP, templates, favorites, and a Notion-style database engine. This project exposes fifty-four routes, all cookie-authenticated, all scoped to one hardcoded workspace, with no email, no background job runner, no public sharing, no export, and no per-page access control.

The shape of the fix. The missing features are not fifty unrelated problems. They cluster behind three architectural unlocks (§3) plus one large pile of pure client work in the editor that needs no server change at all. That editor pile is where the first month should go — it is the most visible gap and the cheapest to close.

03

Three unlocks

Most of the red in that matrix traces back to three missing pieces of plumbing. Build these and roughly two-thirds of the feature list becomes ordinary work.

A. Server-side structured content

Document bodies exist only as a Yjs XmlFragment inside the page-epoch Durable Object. D1 gets a lossy projection — projectDocument() in src/shared/document-projection.ts flattens everything to plain text plus mention targets. The only server-side byte access is GET /api/versions/:id, which returns an opaque application/vnd.yjs blob.

The worker already decodes Yjs to ProseMirror JSON in src/worker/document.ts. Exposing that decode on demand — plus a ProseMirror → Markdown/HTML serializer — unlocks export, public share pages, a REST content API, richer search projections, and link previews that do not need a live client. This is the single highest-leverage item in the report, and docs/API_COMPATIBILITY.md already identifies it as the widest-blast-radius gap.

B. A background job runner

wrangler.jsonc binds D1, R2, two Durable Objects, and static assets. There is no Queues binding, no Workflows binding, and a single hourly cron trigger doing deletion retries. Docmost's file_tasks table and Outline's ~70 task classes exist because export, import, email, notification fan-out, and webhook delivery all need to outlive a request.

Add a Queues (or Workflows) binding plus a jobs table with status and progress. That one addition unlocks email, notification fan-out, whole-tree export, in-app import, webhooks, and search reindexing — six matrix rows behind one binding.

C. A scope column

install_state carries CHECK (id = 1), and getMember() in src/worker/auth.ts resolves membership with an unfiltered LIMIT 1. Every route derives scope from the one workspace that can exist. Keeping that single-tenant decision is fine — but adding a space_id on pages plus a grants table gets you spaces, groups, per-page permissions, personal pages, and share scoping without touching the multi-workspace constraint at all.

04

Gap by gap

Editor · client-only work

The block palette is the default one

Now
notesSchema in src/client/mentions.tsx is defaultBlockSpecs plus one custom mention inline. That means paragraph, headings, lists, checklist, toggle, quote, code, table, and media — and nothing else.
References
Docmost's @docmost/editor-ext adds callouts, inline and block math, Mermaid, Draw.io, Excalidraw, embeds, PDF, columns, status chips, footnotes, page breaks, subpage lists, transclusion, and find-and-replace. Outline ships Math, MathBlock, Notice, Embed, ToggleBlock, and Emoji nodes. AFFiNE adds Mermaid, Typst, and PDF modules.
Build
A block pack: callout, math (KaTeX), Mermaid, columns, embed, table-of-contents, and a synced/transclusion block. All are BlockNote custom specs — zero server change, highest visible payoff per hour in the entire report.
Watch
Every new spec must also be handled in projectDocument(), or its text silently disappears from search, backlinks, and previews.
Organization

One flat tree, no way to file anything

Now
A single page tree with fractional ordering, archive, and trash. No favorites, no pins, no tags, no templates, no recently-viewed, no drafts. The sidebar has exactly three views: search, mentions, settings.
References
Outline: collections, stars, pins, drafts, templates, insights. Docmost: spaces (including personal spaces), labels, favorites, recent, created-by-me, breadcrumbs, duplicate, move-to-space. AFFiNE: collections with rules, tags, favorites, template docs, and a journal for daily notes.
Build
Favorites and recently-viewed first — two small tables and a sidebar section, and they change daily use more than anything else on this list. Then templates (a boolean on pages plus a picker on create), labels, and finally spaces once unlock C exists.
Access

Three global roles and no way to share out

Now
owner / editor / viewer applied workspace-wide by requireOwner / requireEditor in src/worker/auth.ts. No resource-scoped grants, no groups, nothing readable without a session. assertSameOrigin rejects every non-browser caller by design.
References
Docmost has page_access + page_permissions keyed to a user or a group. Outline has collection memberships, document memberships, group memberships, and access requests. Both publish share links; Outline's Share model alone carries includeChildDocuments, custom domain, allowIndexing, showTOC, showLastUpdated, a view counter, and revocation.
Build
Public share links are the headline feature and, on this architecture, unusually cheap: a token table in D1 plus an unauthenticated route that renders HTML from the R2 snapshot rather than waking the Durable Object. That makes shared pages edge-cacheable and costs nothing when nobody is editing — better than any of the three references manage.
Then
Groups, then per-page grants checked alongside the existing role check.
Discovery

Search is one query with no controls

Now
GET /api/search — FTS5 prefix-AND over title and flattened body, ranked by bm25, hard LIMIT 30. No pagination, no filters, no archived results, and comments and attachment text are not indexed at all. Results also trail edits by the 30-second compaction cycle.
References
Outline's documents.search filters by collection, author, date range, and status, keeps a SearchQuery history, and has a separate search_titles endpoint for the quick switcher. Docmost indexes attachment contents and uses pg_trgm and unaccent for fuzzy and accent-insensitive matching. AFFiNE runs a dedicated indexer plugin with embeddings.
Build
Add filters, pagination, and a title-only endpoint to what exists — a day's work that makes the current index feel three times bigger. Then index comments and extracted attachment text. Vectorize for semantic search is a later, optional layer.
Data portability

Nothing comes out; only a CLI puts things in

Now
No export of any kind. Import is pnpm import:notion, an operator-machine script driving the public API.
References
Outline exports Markdown zip, HTML zip, JSON, and TextBundle, per document or per collection or whole-instance, and imports docx/markdown/html plus Notion and Confluence through queued Import / ImportTask records. Docmost exports Markdown, HTML, and PDF for a page or a whole space with children, and runs imports through file_tasks with progress in the UI.
Build
Per-page Markdown and HTML export falls straight out of unlock A and can ship on its own. Whole-tree zip export and in-app import both need unlock B. PDF needs the Browser Rendering binding — the one thing here that cannot be done in-worker.
Engagement

Nothing ever tells anyone anything

Now
A polled mention inbox (member_mentions + mention_reads) is the entire notification system. Better Auth is configured with emailAndPassword and no mailer, so there is no password reset, no email verification, and invites are copy-a-link only. Comments live in a Y.Map the server never reads, so a comment mention notifies nobody.
References
Outline has a Notification model, a Subscription model, email digests, and roughly twenty-five notification task types. Docmost added notifications and watchers tables with a backfill migration and a queue processor. Both send real email.
Build
Watchers plus an in-app notification feed, pushed live over the existing WorkspaceEvents Durable Object rather than polled. Email fan-out rides on unlock B. Making comments visible to the server — writing thread metadata to D1 on compaction — is what turns comment mentions into notifications and makes comments searchable.
Identity

Collaborators have no faces and no names

Now
Email and password only. No profile page, no avatar, no session list. In src/client/EditorPage.tsx, resolveUsers returns the literal string "Collaborator" for every user who is not you — so every comment by anyone else is attributed to a nameless stranger.
References
Docmost ships MFA, LDAP, SCIM, and SSO with group sync, plus user session management. Outline has OIDC, Google, Azure, Slack, Discord, GitHub, GitLab, and passkeys as first-class plugins.
Build
Fix resolveUsers first — it is a small endpoint and a cache, and it repairs comment attribution, presence labels, and mention chips at once. Then profiles and avatars, then password reset once mail exists, then Better Auth's OIDC and two-factor plugins.
Structured data

Tables are a spreadsheet, not a database

Now
Five column types — text, number, checkbox, date, select — with a 60-second single-editor lease, 20,000-row cap, and server-side paging and sorting. No saved views, no filters, no grouping, no relations, no formulas, no CSV.
References
Docmost's bases carry typed properties with type_options, formulas, and a staged type-migration path (pending_type, pending_token) so a column can change type without losing data. AFFiNE has database blocks embeddable inside a page. Outline deliberately offers none of this.
Build
Saved views (filter, sort, group) and more property types — multi-select, person, URL, created/updated by — before anything exotic. Then CSV import/export, then an inline database block inside a document.
Note
The lease model is the one place the app abandons its own realtime story. Moving table state into a Durable Object would make tables collaborative like documents and delete table_leases entirely.
Interface

No dark mode, no shortcuts, no other languages

Now
theme="light" is hardcoded on the BlockNote view and styles.css has no prefers-color-scheme block at all. No command palette, no keyboard shortcut layer, no emoji picker for page icons, no cover images, no localization scaffolding, no PWA manifest.
References
All three ship dark mode and translate through Crowdin — Docmost advertises ten-plus languages. AFFiNE adds quick search, peek view, find-in-page, and a theme editor.
Build
Dark mode as a token pass over styles.css, and a Cmd-K quick switcher on the new title-search endpoint. Both are afternoon-sized and both are the first thing anyone notices is missing.
Extensibility

Nothing can talk to it but the browser

Now
Fifty-four routes, all authenticated by session cookie, all origin-locked. No tokens, no webhooks, no integrations. Document content cannot be read or written over HTTP at all.
References
Outline is API-first: thirty-nine resource areas, API keys, OAuth clients with dynamic registration, a webhooks plugin, and twenty-four integration plugins. Docmost added API keys and an audit log.
Build
A personal access token table plus a bearer branch in the auth middleware — docs/API_COMPATIBILITY.md already sketches the exact shape, and the existing invite code gives you the hash-only storage pattern to copy. Read-only content endpoints first; writes are genuine distributed-systems work because a REST edit has to become a Yjs transaction against a possibly-hibernating object.
05

Build order

Ordered by visible gain per unit of work, not by size. Tier 1 needs no schema change and no new binding.

Tier 1 — ship without touching the architecture

weeks, not months

Every item here is client-side or a single new D1 table. Together they close most of the perceived quality gap.

  1. 01Editor block packCallout, math, Mermaid, columns, embed, table of contents. Extend projectDocument() in the same commit so the new text stays searchable.
  2. 02Dark modeToken pass over styles.css, drop the hardcoded theme="light", respect the OS preference with an explicit override.
  3. 03Cmd-K quick switcherNeeds a title-only search endpoint, which the search work wants anyway.
  4. 04Real collaborator identityReplace the "Collaborator" placeholder with a member lookup; add profiles and avatars. Fixes comments, presence, and mentions at once.
  5. 05Favorites and recently viewedTwo tables, one sidebar section. Disproportionate effect on daily use.
  6. 06Search filters and paginationAuthor, date, kind, archived, plus a cursor. The index already exists.
  7. 07Page templatesA flag on pages and a picker on the create path.
  8. 08Keyboard shortcuts and a help overlayTable-stakes for a wiki people live in all day.

Tier 2 — behind the three unlocks

a quarter

Each one depends on unlock A (server-side content), B (job runner), or C (scope column).

  1. 09Markdown and HTML exportUnlock A. The first user-visible proof that content escapes the CRDT.
  2. 10Public share linksUnlocks A and C. Render from the R2 snapshot so shared pages are cacheable and never wake a Durable Object.
  3. 11Notifications, watchers, and emailUnlock B. Push the in-app feed over the existing WorkspaceEvents object; queue the email.
  4. 12Spaces and groupsUnlock C. Adds the container everything else wants to scope to.
  5. 13Per-page permissionsUnlock C. A grants check layered under the existing role check.
  6. 14In-app importUnlock B. Move notion-import.mjs onto the job model and give it a progress UI.
  7. 15Personal access tokens and a read APIUnlock A. Bearer branch in auth, hash-only storage, read endpoints first.
  8. 16Comments visible to the serverUnlock A. Project thread metadata to D1 so comments notify, search, and survive a schema bump.

Tier 3 — larger bets

deliberate scope calls

Worth doing, but each is a project rather than a feature. Decide these one at a time.

  1. 17Database views and property typesPlus moving table state into a Durable Object so tables become collaborative and the lease disappears.
  2. 18SSO, two-factor, session managementBetter Auth plugins carry most of it; SCIM does not.
  3. 19PDF exportNeeds the Browser Rendering binding. The only item here that cannot run in-worker.
  4. 20Semantic searchVectorize alongside FTS5, with embeddings written on the same compaction pass.
  5. 21Audit log, page views, insightsAn events table plus the read paths Outline models as View and DocumentInsight.
  6. 22WebhooksUnlock B plus a delivery table with retry and signature.
  7. 23Multi-workspaceDrop CHECK (id = 1) and thread workspace_id through every route. Worth asking first whether the product wants it.
06

What not to copy

Five things the reference projects do that this architecture should decline, and one it should stop apologizing for.

  • AFFiNE's edgeless whiteboard. BlockSuite is an enormous surface, and an infinite canvas grows a Y.Doc in exactly the direction the 16 MiB warning and 24 MiB read-only ceiling in src/worker/document.ts cannot absorb.
  • Server-side image processing. Docmost uses sharp for avatar and icon resizing; that is a native libvips binary and will never load in a V8 isolate. Use Cloudflare Images or resize in the browser before upload.
  • Per-keystroke cross-document indexes. Search, backlinks, and previews trailing the compaction cycle is inherent to one-object-per-document, not a bug to chase. Say so in the UI instead — a quiet "indexed a moment ago" beats a fix that cannot exist.
  • Redis-shaped job semantics. BullMQ and Bull assume blocking commands and a long-lived worker loop. Queues, Workflows, and Durable Object alarms are the native answer; re-express the jobs rather than emulating the queue.
  • Multi-tenant billing, quota, and licensing. AFFiNE's payment, quota, entitlement, and license modules exist because it sells a cloud. A self-hosted single-workspace wiki carries that weight for nothing.
  • And the one to stop apologizing for: permanent Durable Object placement and the resulting transatlantic latency is a real limit, but it only affects initial load and cursor sync — Yjs local echo hides typing entirely. Document it as a deployment consideration, not as a defect.
