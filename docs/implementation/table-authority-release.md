# Table authority implementation and release acceptance

This is local implementation evidence, not a production release. The source baseline is `9c06454a828e5d30092769675d831a2789d3a4cd`. Production migration, deployment SHA, feature enablement, sustained load measurements and Phase 7 closeout still require a recorded release run.

## Authority and mixed rollout

`TABLE_AUTHORITY_ENABLED` defaults to false. Deploy the SQLite `TableAuthority` binding, readers, command routes and D1 migrations before allowing an owner to migrate a table. D1 tables keep the existing lease protocol. A migrated table stays authoritative even if the creation flag is subsequently disabled; never reopen its D1 writer path during rollback or outage.

The owner migration fences D1 writers by registry generation, releases only the owner's own current lease, resolves NFKC name collisions with deterministic suffixes, establishes conservative seed row revisions, and seeds original row/property/option IDs in bounded batches. Hashes cover typed cells, row identities/revisions/metadata, property configurations/generations, option labels/colors, saved views and retained person labels. The registry switches to `do` after count/hash parity and a complete projection rebuild. A paused seed stays fenced and resumes against the same generation. D1 triggers reject direct table writes outside the projector's scoped transaction context.

Commands use signed current authorization, per-actor operation receipts and optional table/cell/property/view revision guards. The authority commits its SQLite state, formula cache and durable projection steps before returning. Projection batches are idempotent and bounded; a pending projection is reported separately from canonical commitment. Task, Slack task and captured-task writes use the same command authority after migration. Capture publication keeps its page/row/receipt effects in one guarded D1 batch and cancels the canonical row if the destination guard fails. Generic MCP/legacy writes receive an upgrade response after migration; they cannot bypass the authority.

Repair records its intent before acquiring the D1 fence, then resumes fence acquisition, pending-effect drain, header rebuild, row rebuild and parity verification from durable progress. Alarms resume repair before ordinary projection. Rebuild batches do not advance projection markers until parity succeeds; failed repair remains fenced. New projection compaction preserves command order, and recognized unfinished legacy insert segments recover in dependency order. Completed projection payloads are removed after their durable watermark; retention keeps the newest 100 completed events, every pending event and all operation receipts. Initial seed retries preserve their frozen D1 source and original identities. Migrated AI reads advance revision-bound offsets across chunks; row search resolves select, status and multi-select labels from canonical options.

WebSockets send revision invalidations; clients reload the authoritative query and reconnect after interruption. Linked hosts poll and use host-scoped query/command routes. This is not an offline edit queue. Lease endpoint removal is deferred until every table has migrated and all integrations have completed live acceptance.

## Views, properties and calculations

Saved Grid is the first creation capability. `TABLE_BOARD_ENABLED` and `TABLE_CALENDAR_ENABLED` separately gate new layouts and changes to those layouts, default false. Existing definitions remain readable and same-layout updates remain available when creation is disabled. All layouts use the same typed filters, ordered sorts, stable row-ID tie breaker and revision-bound pagination; group counts and calculations cover the complete filtered set before pagination. Invalid definitions fall back visibly to Grid. Browser queries load bounded pages instead of all 20,000 rows.

Board insertion applies conservative equality defaults first, then explicit group assignment in the same command. Calendar keeps unscheduled rows visible, groups timestamp days in the viewer timezone, preserves a fixed timestamp offset or a property's IANA wall-clock rule across day drags, and rejects nonexistent DST local times. Person cells use a member picker and retain former-member names without allowing new assignment or granting access. Metadata fields are server maintained. Stable option IDs survive option deletion as explicit missing-option markers.

Equality insertion defaults exclude formulas and metadata. Settings drafts retain their original property/view revisions during remote updates and offer an explicit reload after a conflict. Filter controls submit the backend's typed values, including collection ID arrays. Calendar move commands may include the display timezone to land on the selected viewer day while retaining the source clock; omitted timezone preserves the earlier date-replacement behavior.

Property names use the same NFKC key in authority validation and the D1 partial unique index. Configuration has an explicit `version: 1` distinct from property revision and generation; unsupported versions are rejected. Legacy rows keep a null name key until verified migration. Type conversion stores converted values in a durable staged generation while originals remain active. Previews include converted, empty, invalid and total counts plus the schema revision; created/deleted rows update staging. Commit checks the schema and original cell revisions and activates staged values atomically. Cancellation preserves originals. Arrays are never guessed into scalar text.

Formula ASTs are compiled on the Worker from source and authoritative property IDs; browser ASTs are ignored. `prop()` retains option-ID semantics. `OptionLabel(prop("Status"))` resolves a select/status ID to its displayed label, returns null for an empty value and reports a formula error for unknown or unsupported IDs. Formula types, dependencies and option lookups are prepared once per command, seed or export and reused across rows. Option-definition changes recompute label-dependent formulas. Select/status conversions to text also use displayed labels; option changes are blocked while that property's conversion is pending. Computed caches and source stamps activate atomically with schema changes. Row stamps use the actual persisted row revision, while schema-only recalculation advances the schema/table revisions. D1 computed values and saved-view/person tables are disposable projections; view queries read the authority. Template clones capture a revision-bound canonical snapshot, remap property/option/row/view IDs and formula dependencies, retain captured tags on retries and restart partial staging from the captured snapshot. Fresh clones remain D1 until explicitly migrated.

Relations and rollups are future work. Stable IDs, dependency IDs and explicit row/schema/table revisions are prepared for that work; no relation storage, cross-table subscriptions or rollup evaluator is active.

Task-list templates and cloning remain unsupported. Creation, instantiation, retries and cached workflows reject task-list pages or captured task snapshots before publication. Failure cleanup removes only job-owned staged resources and preserves published or newer-attempt targets.
